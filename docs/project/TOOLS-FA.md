# استفاده از ابزارهای توسعهٔ تعمیران

نصب و بررسی: ۱۰ نوامبر ۲۰۲۶. این ابزارها در محیط توسعهٔ Codex هستند؛ هاست نصب‌شدهٔ تعمیران همچنان PHP/MySQL است.

نصب ثبت‌شده در این راهنما مختص محیط همان اجراست و همراه clone مخزن منتقل نمی‌شود. در محیط تازهٔ بررسی جریان کاری، این مهارت‌ها/CLIها موجود نبودند؛ [گزارش اجرا و جایگزین‌های استفاده‌شده](../reports/hosting/2026-11-10-workflow-review-FA.md) وضعیت واقعی را ثبت می‌کند. پیش از هر اجرا، حضور ابزار را در همان محیط بررسی کنید.

در Codex یک نشست تازه در `/workspace/repos/tamiran` باز کنید. فهرست `/skills` باید `impeccable`، `code-simplification`، `ui-ux-pro-max` و `graphify` را نشان دهد. عبارت‌های دارای `$` در این راهنما **پیام داخل چت Codex** هستند؛ آن‌ها را در Bash وارد نکنید. فرمان‌های بخش ترمینال از ریشهٔ مخزن اجرا می‌شوند.

## ابزارهای آماده و روش استفاده

### Impeccable — اصلاح رابط موجود

نسخهٔ مهارت و CLI نصب‌شده `4.8.2` است. از یکی از این پیام‌ها استفاده کنید و هر بار یک صفحه یا بخش مشخص را هدف بگیرید:

```text
$impeccable audit فرم پذیرش نسخهٔ PHP تعمیران را از نظر کیبورد، خوانایی، خطاها و موبایل بررسی کن؛ فعلاً گزارش بده.
$impeccable distill داشبورد تعمیران را خلوت‌تر کن؛ اطلاعات کاری و عملکرد موجود حفظ شود.
$impeccable polish فرم ورود نسخهٔ PHP را با حفظ فارسی، RTL و هویت بصری فعلی اصلاح کن.
$impeccable adapt صفحهٔ پذیرش را برای نمایش موبایل اصلاح کن.
```

`audit` برای بررسی فنی رابط، `critique` برای نقد تجربه و طراحی، `distill` برای کاهش شلوغی، `polish` برای اصلاح جزئیات و `harden` برای خطاها، سرریز محتوا و حالت‌های مرزی است. `init` زمینهٔ محصول را در `PRODUCT.md` و `document` نظام بصری موجود را در `DESIGN.md` ثبت می‌کند؛ برای شروع استفادهٔ محدود، اجرای همهٔ این‌ها لازم نیست.

در ترمینال، ابزار تشخیص بدون اجرای مدل قابل استفاده است:

```sh
impeccable --version
impeccable detect hosting/frontend/src --json
impeccable detect hosting/frontend/public/assets/accessibility.css --json
```

خروج `0` یعنی اسکن انجام شد و یافته‌ای نبود؛ `2` یعنی اسکن یافته دارد؛ `1` یعنی اسکن انجام نشد. بررسی فایل JSX/TSX جای بررسی صفحهٔ اجراشده را نمی‌گیرد؛ کنتراست و اندازهٔ واقعی متن به صفحهٔ محلیِ آماده نیاز دارند. نصب این نوبت شامل مهارت بومی و CLI است؛ hook خودکار یا live mode فعال نشده است. اگر بعداً live mode خواستید، از مسیر گفت‌وگوی فعلی و `IMPECCABLE_LIVE_COPY_AGENT=chat` استفاده کنید تا Apply به اجرای مستقل با مجوزهای متفاوت منتقل نشود.

### Code Simplification از Addy — ساده‌سازی کد با حفظ رفتار

نام واقعی مهارت نصب‌شده `code-simplification` است؛ `code-simplify` نام میان‌بر در مجموعهٔ کامل بالادستی است.

```text
$code-simplification فایل hosting/frontend/src/app/software/case-mutations.ts را بررسی کن؛ ابتدا مسئولیت‌ها و تست‌های لازم را مشخص کن، سپس فقط پیچیدگی غیرضروری را با حفظ رفتار کم کن.
```

هدف، خوانایی و نگهداری بهتر است. مجوز سرور، validation، idempotency، rollback و خطاها برای کوتاه‌کردن کد حذف نمی‌شوند. تغییر هر بار محدود باشد و با آزمون متناسب بررسی شود. منابع کمکی مجموعه همراه همین مهارت نصب شده‌اند؛ سایر مهارت‌های Addy در این نوبت نصب نشده‌اند.

### ECC — برنامه‌ریزی، امنیت و تأیید تغییرات

ECC در این پروژه قواعد و نقش‌های Codex دارد. نام نقش‌ها در `.codex/config.toml` ثبت شده است: `explorer`، `planner`، `security_reviewer`، `frontend_reviewer`، `database_reviewer` و `verifier`. درخواست را به زبان معمولی بنویسید:

```text
با ECC و نقش security_reviewer مجوزهای API ثبت پذیرش نسخهٔ PHP را بررسی کن؛ یافته‌ها را با فایل و شاهد گزارش بده.
با ECC verification-loop تغییرات فعلی را بررسی کن و تست‌های اجراشده و اجرا‌نشده را جدا بنویس.
```

برای هر کار فقط نقش لازم انتخاب شود. قواعد و نقش‌ها مدل یا سطح مجوز نشست را تغییر نمی‌دهند. دستورهای تمام پلتفرم‌های README بالادستی الزاماً فرمان قابل اجرای این نصب نیستند.

### UI UX Pro Max — انتخاب الگو و ساختار رابط

```text
$ui-ux-pro-max برای جدول صف تعمیر، فیلتر وضعیت و فرم پذیرش تعمیران الگوی مناسب پیشنهاد بده؛ فارسی RTL، استفادهٔ روزانه و موبایل را مبنا قرار بده.
```

این مهارت برای تصمیم‌های کلی رابط و الگوها مناسب است. سپس می‌توان یک بخش مشخص را با Impeccable بررسی و اصلاح کرد. برای یک تغییر کوچک، اجرای هم‌زمان همهٔ مهارت‌های طراحی لازم نیست.

### Graphify — پیدا کردن مسیر و وابستگی‌ها

```text
$graphify مسیر ثبت پذیرش در نسخهٔ PHP تعمیران را از رابط تا API و سرویس خصوصی پیدا کن؛ روابط مهم را با سورس تأیید کن.
$graphify /workspace/repos/tamiran --update
```

نمونهٔ اول پرس‌وجو است؛ نمونهٔ دوم استخراج را به‌روز می‌کند. در ترمینال:

```sh
graphify query "tamiran_require_actor" --budget 1500
```

نمای مرتب در `graphify-out/graph.html` و نمای انبوه در `graphify-out/graph-full.html` است. پس از تغییر واقعی گراف، نمای مرتب با `python3 scripts/build_project_map.py` ساخته می‌شود. به‌روزرسانی باید مرز PHP، Worker و مرجع منجمد، روابط موازی و قابلیت آفلاین HTML را حفظ کند؛ دستور exporter خام می‌تواند نمای مرتب را بازنویسی کند، پس بازسازی کامل را به نشستِ آشنا با AGENTS.md بسپارید.

### Ruflo — هماهنگی مراحل، پس از بازیابی دفتر ثبت

Ruflo نصب است، ولی دفتر ثبت سیاست همین checkout خطای `policy-anchor-log-missing` و در بررسی بازیابی خطای `policy-ledger-truncated` دارد. ثبت خودکار وظایف فعلاً قابل استفاده نیست. نصب مهارت‌های جدید این مشکل را برطرف نمی‌کند. فایل‌های اصلی سیاست باید از پشتیبان معتبر برگردند؛ حذف anchor یا ساختن سابقهٔ مصنوعی راه بازیابی نیست.

برای دیدن تعریف مراحل و پیش‌نیازها در ترمینال:

```sh
python3 scripts/tamiran_flow.py plan
python3 scripts/tamiran_flow.py doctor
ruflo policy status
```

`doctor` پیش‌نیازها را بررسی می‌کند؛ سلامت دفتر ثبت جدا با `ruflo policy status` مشخص می‌شود. پس از بازیابی و تأیید سلامت، شروع هدایت‌شده در همین نشست:

```sh
python3 scripts/tamiran_flow.py start --task "شرح دقیق کار" --profile tooling
```

پروفایل `tooling` برای ابزارها و مستندات، `organization` برای نظم‌دهی و نقشه، `frontend-static` برای رابط و `backend-local` برای PHP/SQL محلی است. پروفایل متناسب انتخاب شود. `start` فقط مراحل را ثبت می‌کند؛ `run` اجرای مستقل و ترتیبی Codex CLI را آغاز می‌کند. ادامه و ثبت شواهد در [راهنمای کامل Ruflo](../ruflo/WORKFLOW-FA.md) آمده است.

| Taste Skill | «سایت معرفی و فروش نرم‌افزار تعمیران را طراحی کن.» تمرکز اصلی آن سایت شرکت و صفحات بازاریابی است. |

## ترتیب پیشنهادی برای یک تغییر

ابتدا با Graphify محل تغییر را پیدا کنید؛ با ECC دامنه و معیار پذیرش را روشن کنید. برای طراحی بخش جدید از UI UX Pro Max و برای اصلاح رابط موجود از Impeccable استفاده کنید. اگر کد پیچیده است، یک بازآرایی محدود با `code-simplification` انجام دهید و در پایان تست و بررسی ECC را اجرا کنید. Ruflo پس از رفع مشکل دفتر ثبت می‌تواند ترتیب و شواهد این مراحل را هماهنگ کند.

نتیجه و منشأ نصب در [TOOLS-INSTALLATION.json](TOOLS-INSTALLATION.json) ثبت شده است. نصب در محیط توسعهٔ فعلی انجام شده؛ انتشار راهنما در GitHub، مهارت را خودکار روی دستگاه دیگر نصب نمی‌کند.
