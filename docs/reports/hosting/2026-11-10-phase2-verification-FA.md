# بررسی فاز دو نسخه PHP تعمیران — ۲۰۲۶-۱۱-۱۰

## دامنه و اصلاحات

برآورد تعمیر در محدوده تعمیرگاه و شعبه پرونده بررسی می‌شود و تکنسین نامرتبط نمی‌تواند برآورد بسازد یا ارسال کند. تکرار تحویل قطعه فقط با همان شعبه، درخواست، مقدار و تکنسین مجاز است؛ نهایی‌سازی تکراری نیز همان کنترل مالکیت نهایی‌سازی اولیه را دارد. تأیید حضوری کنترل کیفیت مشروط به شعبه پرونده محدود شده است.

## نتیجه آزمون محلی

- آزمون HTTP نسخه Pro با کنترل کیفیت مستقل و مشروط: ۱۲۸ بررسی موفق، شامل دو شعبه واقعی آزمایشی، درخواست و رزرو دو قطعه، مصرف یکی و بازگشت دیگری، کنترل موجودی، مردودی و بازکاری، تأیید مشروط، تسویه، ممانعت از تحویل پرداخت‌نشده و تحویل مستند.
- مسیر مستقل قبولی کنترل کیفیت بعد از بازکاری: ۱۲۴ بررسی موفق.
- مسیر انبار ساده و کنترل کیفیت خاموش: ۱۰۱ بررسی موفق.
- آزمون پس‌روی ۲۳ بررسی روی ۲۵۱ پذیرش واقعی ساختگی: موفق، شامل صفحه‌بندی، تجمیع و محدودیت مالکیت.
- قراردادهای رابط: ۵ آزمون موفق؛ بررسی نحوی PHP و Python و `git diff --check` موفق.

آزمون‌ها از PHP و MariaDB محلی با حساب‌ها و پرونده‌های ساختگی استفاده کردند؛ پیامک و پرداخت واقعی ارسال نشد. برای ایجاد شعبه دوم از ابزار fixture استفاده شد که فقط به پایگاه `tamiran_test` روی `127.0.0.1:3307` و تعمیرگاه با نام آزمایشی اجازه نوشتن می‌دهد.

## محدودیت شواهد

این نتایج تأیید بصری مرورگر، HTTPS یا آزمون روی هاست عملیاتی نیستند و به معنی استقرار نیستند. بازسازی AST نقشه Graphify در نسخه آزمایشی انجام شد، اما ۱۵ فایل SQL به دلیل نبود استخراج‌کننده SQL پوشش نداشتند و مرزبندی روابط بین نسخه‌ها در خروجی جدید تأیید نشده است. ازاین‌رو نقشه رسمی جایگزین نشد و وضعیت `pending_graphify_refresh` همچنان برقرار است.
