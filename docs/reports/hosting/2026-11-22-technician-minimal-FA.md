## ۲. معماری و رفتار نهایی

فهرست تکنسین فقط دستگاه‌ها و فیلترهای انسانی «همه / در دست اقدام / منتظر / پایان‌یافته» را نشان می‌دهد؛ فهرست تمام وضعیت‌های موتور حذف شده است. نمای ورود، دستگاه، شماره، ایراد، توضیح ضروری و سه تصمیم روشن دارد. بازکردن هیچ انتقالی نمی‌سازد؛ شروع بررسی فقط پس از POST موفق ثبت می‌شود. پروندهٔ شروع‌شده «ادامه کار روی دستگاه» دارد.

میز کار، خلاصهٔ کوتاه، یک کادر **گزارش اقدام انجام‌شده** و دکمهٔ **ثبت گزارش** دارد. عنوان، نوع فعالیت، دسته‌بندی، فرم مالی، فهرست قطعات یا تصویر تزئینی در فرم گزارش نیست. گزارش‌های تازه ابتدا می‌آیند؛ گزارش قدیمی با دکمه بارگذاری می‌شود. اصلاح، رویداد جدیدی با نویسنده/زمان جدید و پیوند به اصل است؛ اصل بازنویسی نمی‌شود.

قطعات، اعلام هزینه، تصاویر، ارجاع، پایان موفق و عدم امکان تعمیر صفحهٔ مستقل همان پرونده‌اند. URL، پرونده و صفحه را نگه می‌دارد؛ Back و Refresh پیش‌نویس را حفظ می‌کنند. هنگام ذخیره، کنترل‌های خروج غیرفعال‌اند؛ در Chromium، بازگشت مرورگر نیز تا پایان ثبت مسدود و closing با beforeunload محافظت می‌شود. fallback مرورگرهای فاقد Navigation API وجود دارد، اما Safari/Firefox در این اجرا آزمایش نشده‌اند.

قطعهٔ آزاد با انبار فعال مجاز است. فرم آزاد چند ردیف دارد؛ اگر ردیف دوم شکست بخورد، ردیف ثبت‌شده مشخص و ردیف باقی‌مانده محفوظ است. retry مصرف/قیمت را دوباره ثبت نمی‌کند. قطعهٔ انبار تنها پس از تحویل قابل مصرف/مرجوعی است. همهٔ مبلغ‌های ورودی و نمایش تومان‌اند و قرارداد API همچنان ریال صحیح است.

اعلام هزینه، برآورد و انتظار معتبر مشتری را مدیریت می‌کند؛ تکنسین دکمهٔ تأیید صوری ندارد. گزارش در انتظار هزینه یا قطعه همچنان قابل ثبت است. ارجاع، درخواست تحویل مسئولیت است؛ مسئول و نتیجه تا پذیرش مقصد تغییر نمی‌کنند. هیچ مجوز تازه‌ای برای تکنسین ساخته نشده است. قطعات/تعهدهای قبلی پیش از پذیرش باید طبق قواعد موجود تعیین تکلیف شوند.

پایان موفق، گزارش نهایی و مقصد مجاز را نشان می‌دهد؛ سرور QC فعال یا مالی را انتخاب می‌کند. عدم امکان تعمیر یک علت آزاد می‌خواهد؛ بدون QC و پس از تعیین تکلیف قطعه/مالی به مسیر تحویل می‌رود. قاعدهٔ تأییدشدهٔ مالک حفظ شد: فاکتور پیشنهادی تعمیرنشده فقط عیب‌یابی و قطعات مصرف‌شده دارد، بدون اجرت تعمیر و ضمانت تعمیر. دکمهٔ پیگیری مالی برای تکنسین، درخواست قابل پیگیری در پرونده ثبت می‌کند؛ تأیید، پرداخت یا اعلان مالی ساختگی نیست.

## ۴. Backend و Schema

Schema و تعداد ۳۸ endpoint تغییر نکرده‌اند؛ migration لازم نیست. پذیرش/اجبار انتقالِ درخواست باز روی پروندهٔ قفل‌شده اکنون سروری رد می‌شود؛ لغو اداریِ درخواست بدون تغییر مسئول همچنان مجاز است. توسعه‌ها روی همان رویداد JSON، فایل خصوصی و تحویل مسئولیت موجودند. title برای گزارش تازه اختیاری است؛ کلاینت‌های قدیمیِ دارای عنوان همچنان کار می‌کنند. correctsActivityId اختیاری باید به رویداد technical_activity همان پرونده اشاره کند؛ رویداد اصلی حذف نمی‌شود. مجوز Shop، Branch، مسئول/همکار، قفل، CSRF و Session سروری باقی‌اند.

idempotencyKey ارجاع اختیاری و سازگار با کلاینت قدیمی است؛ کلاینت تازه retry پایدار دارد. ارجاع، audit و رویداد replay زیر قفل پرونده در یک تراکنش‌اند. قواعد انتقال دارایی و پذیرش مقصد تغییر نکرده است. projection وضعیت مالی برگشت از محاسبهٔ موجود استفاده می‌کند تا پروندهٔ رایگان، بی‌دلیل «فاکتور صادر نشده» را مانع نبیند؛ محاسبات مالی عوض نشده‌اند.

بازبینی مسیر خطای تحویل مسئولیت، اشتباه گرفتنِ دسترسی همکار با مالکیت مسئول را آشکار کرد؛ کنترل به بررسی مسئول اصلی تغییر کرد و سه بررسی اختصاصی، علت قطعهٔ باز و حفظ مسئول را تأیید کردند.

خطای اولیهٔ بازگشت هنگام ثبت در مرورگر شناسایی و محافظ Navigation API به همراه fallback افزوده شد؛ تست نگه‌داشتن پاسخِ commit‌شده و تلاش برای Back اکنون موفق است. قطعی پاسخ پس از commit فقط یک گزارش می‌سازد. شکست ردیف دوم قطعه، ردیف اول را دوباره ثبت نمی‌کند. ۵۲ گزارش از طریق بارگذاری قدیمی‌تر حفظ شدند. پیش‌نویس در ابزارها، Back و Refresh حفظ شد.

برای تکرار، fixture خصوصی را با `technician_workbench.py --browser-fixture /tmp/private-fixture.json` بسازید؛ سپس `technician_minimal_api.py --fixture ... --report ...` و `technician_minimal_browser.py --fixture ... --output ...` را اجرا کنید. اعتبارنامه‌ها فقط مصنوعی و بیرون مخزن باشند. تمام ابزارهای HTTP مقصد غیر loopback را رد می‌کنند.

## ۷. ریسک‌ها و تست‌های اجرا‌نشده

نتیجهٔ ناموفق باز در مجموعه‌های نهایی نیست. Safari/Firefox، خوانش‌گر صفحه، نفوذ بیرونی و تأیید واقعی مشتری/OTP آزمایش نشده‌اند. پیامک یا پرداخت واقعی و تأیید صوری مشتری ثبت نشد. بازبین انسانی یا عامل دوم مستقل به کار نرفته و تأیید مستقل انسانی ادعا نمی‌شود؛ بازبینی ساختاری و عملکردی با شواهد جدا ثبت شده است. محافظت مرورگرهای فاقد Navigation API فقط از مسیر fallback و beforeunload استفاده می‌کند و تأیید Safari به تست مستقل نیاز دارد.

Schema، مجوز تازه و تصمیم تجاری باز لازم نیست. تعهد قطعات/داغی می‌تواند پذیرش ارجاع را متوقف کند؛ این مانع با پنهان‌کردن UI حذف نشده است. ماژول تجاری قفل‌شده خودکار باز نمی‌شود. فاکتور تاریخی خودکار بازنویسی نمی‌شود؛ اصلاح مالی با نقش مجاز باقی است.

سه بررسی API تکمیلی نیز بسته‌شدن پرونده پس از درخواست ارجاع را آزمودند: پذیرش مقصد رد شد، مسئول و قفل حفظ شدند و مدیر توانست درخواست معلق را بدون انتقال مسئول لغو کند.

## ۸. Commit، انتشار و هاست

نسخهٔ php.9، بستهٔ نصب تازه، سورس و update از php.8 دارد. نصب/ارتقا در محیط محلی با حفظ config، کلیدهای خصوصی، عکس و پروندهٔ قبلی بررسی و موفق شد. مطابق مجوز AGENTS، سورس پس از تأیید با Commit و Push عادی به main می‌رود؛ نتیجهٔ SHA در پاسخ تحویل گزارش می‌شود. Force Push و Deploy روی هاست عملیاتی انجام نمی‌شود.
