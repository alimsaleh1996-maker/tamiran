# بررسی و اصلاح رابط کاربران و دسترسی‌ها — php.4

فرم کاربران تعمیرگاه در نسخهٔ `2.0.0-php.4` بازطراحی شد. اطلاعات حساب، نقش و شعبه، و دسترسی‌های تکمیلی بخش‌های مستقل دارند؛ مجوزها بر اساس کار تعمیرگاه گروه‌بندی و جزئیات اختیاری در شروع بسته‌اند. چیدمان راست‌به‌چپ و رنگ و فونت موجود تعمیران حفظ شده است.

## روش و دامنه

اسکیل درخواستی [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) از commit ثابت `2de1134dc4d1cfe112934611ae5803ae17a1bd7e` خوانده و اجرا شد. راهنمای اصلی، قواعد محصول و بخش‌های مرتبط quick-reference مبنای بررسی بودند. جست‌وجوهای هدفمند UX و React برای برچسب صریح، خطای کنار فیلد، فاصلهٔ کنترل‌ها و بازچینی واکنش‌گرا استفاده شدند. جست‌وجوی مجزای «progressive disclosure» نتیجهٔ مرتبط نداد؛ تقسیم به شش گروه تصمیم طراحی مبتنی بر وظایف همین محصول است، نه خروجی ادعایی آن جست‌وجو.

تصویر ارسالی کاربر نقطهٔ شروع بود. سپس وضعیت واقعی قبل از تغییر روی PHP 8.2.35 و MariaDB 10.11، با دادهٔ کاملاً مصنوعی ثبت شد. در نسخهٔ محلی CSS قدیمی بارگذاری می‌شد؛ بنابراین از عکس کاربر نمی‌توان علت cache را قطعی دانست. نسخهٔ جدید CSS اختصاصی دارای هش دارد و حالت باقی‌ماندن stylesheet مشترک قدیمی جداگانه آزموده شد.

مرورگر تعاملی محیط با خطای داخلی اتصال باز نشد. به‌جای آن Chromium واقعی از runner پروژه برای تصویر، کلیک، کیبورد، ارسال فرم و خواندن نتیجهٔ API استفاده شد. درخواست‌ها فقط به loopback بودند. مرورگر مجازیِ داده یا API mock برای ساخت و ویرایش کاربر استفاده نشد؛ تنها سناریوی صریح cache، فایل CSS قدیمی را جایگزین کرد.

دامنهٔ عمیق: تنظیمات ← کاربران و نقش‌ها، ایجاد/ویرایش، شعب و مجوزها. بررسی نمونه‌ای: داشبورد، مرحلهٔ نخست پذیرش و صفحهٔ مالی در وضعیت بدون پرونده. همهٔ بیست منو و تمام وضعیت‌های پرونده بررسی انتهابه‌انتها نشده‌اند.

## راستی‌آزمایی

- ۲۲ بررسی مرورگری اصلی موفق: ساخت واقعی کاربر و موبایل فارسی، تغییر نقش و حفظ مجوز، نقش مدیر، خطای محلی نام/موبایل/ایمیل، پوشیده‌بودن رمز، گروه‌ها، تمرکز، cache قدیمی و نبود خطای JavaScript.
- سه بررسی نهایی روی build نسخهٔ php.4 موفق: تطبیق نام فارسی/عربی، بازگشت تمرکز به دکمهٔ همان کاربر و فاصلهٔ متن رمز از دکمهٔ نمایش در RTL/LTR.
- نبود اسکرول افقی صفحه در عرض‌های ۱۰۲۴، ۷۶۸، ۳۹۰ و ۳۲۰ پیکسل بررسی شد. تصاویر نهایی دسکتاپ و موبایل باز و بازبینی شدند.
- ۳۰ آزمون واقعی HTTP/SQL مدیریت کاربران مجدداً موفق: مرز تعمیرگاه و شعبه، نقش و مجوز، CSRF، ابطال نشست، تراکنش audit و سقف سهمیه در دو نشست مستقل.
- TypeScript، build، شش ورودی Node، ۶۷ هش مرجع منجمد و دو آزمون بسته‌بندی موفق؛ نحو دو PHP دارای تغییر نسخه نیز صحیح است. هشدار موجود chunk بزرگ‌تر از ۵۰۰KB باقی است.
- شواهد قابل خواندن: [مرورگر](user-management-2026-11-19/ui-results.json)، [بازبینی نهایی](user-management-2026-11-19/final-ui-results.json)، [HTTP/SQL](user-management-2026-11-19/http-results.json).

این بررسی گواهی دسترس‌پذیری یا ممیزی امنیتی کامل نیست؛ صفحه‌خوان، Safari/iOS و هاست واقعی بررسی نشده‌اند. مدل مجوزهای سمت سرور در این انتشار تغییر نکرده؛ نقش سفارشی جدید اضافه نشده است. یافته‌های قبلی مربوط به ACL فایل‌ها، محدودیت گزارش خطا و چرخهٔ رمز موقت همچنان مستقل‌اند. وضعیت بررسی بستهٔ نصب و ارتقا در فایل release-verification کنار ZIPها ثبت می‌شود.
