# شواهد نسخهٔ PHP تعمیران

نسخهٔ جاری: `2.0.0-php.2` — تکمیل اصلاحات رابط: ۲۴ اکتبر ۲۰۲۶.

## بررسی‌های نسخهٔ جاری

| بررسی | نتیجه |
|---|---|
| رابط در Chromium با PHP/MariaDB واقعی | ۳۵ موفق؛ شامل خطا و retry، snapshot قبلی، کیبورد محصول، فوکوس/Escape پنجره‌ها و کشو، تقویم داخلی، Back/Forward، کنتراست نمونه‌های قابل‌اندازه‌گیری و نمایش موبایل |
| API کپچای صوتی | ۱۴ موفق؛ عدم انتشار پاسخ متنی، WAV معتبر، عدم تغییر چالش با پخش مجدد، وابستگی به نشست/شناسه، مصرف یک‌باره و رد درخواست cross-site |
| ساختار صوت و مرز انقضا | ۱۶ موفق؛ هر هشت فایل فارسی، ساختار PCM/RIFF، کلید نادرست، state مصرف‌شده، مرز زمان و ورودی نامعتبر |
| تست اصلی API | ۷۸ موفق روی کد جدید؛ ورود، نقش‌ها، پذیرش، نسخه‌ها، گردش تعمیر و مالی آزمایشی |
| TypeScript و ساخت رابط | موفق؛ Node فقط برای ساخت محلی استفاده شده است |
| نحو PHP | موفق برای APIها، سرویس‌های خصوصی و تست صوت |
| مرجع منجمد | ۶۷ hash، بیست منو و ۲۷ قرارداد بدون تغییر |

داده‌ها مصنوعی‌اند. تصویر و صدای کپچا برای یک چالش تولید می‌شوند؛ JSON فقط metadata دارد، پاسخ متنی ندارد و دریافت صوت انقضا را تمدید نمی‌کند. اجرای صوت روی هاست فقط PHP و فایل‌های ضبط‌شدهٔ همراه بسته را لازم دارد؛ موتور TTS یا سرویس خارجی در زمان استفاده فراخوانی نمی‌شود.

بستهٔ update فقط برای نسخهٔ `2.0.0-php.1` است و شامل SQL، نصب‌کننده، config یا کلیدهای runtime نیست. نصب تازه و به‌روزرسانی از ZIP پس از بسته‌بندی جداگانه بررسی می‌شوند؛ نتیجهٔ نهایی هر artifact کنار ZIPها در فایل `release-verification-2.0.0-php.2.json` ثبت می‌شود.

اجرای واقعی صفحه‌خوان، گواهی کامل WCAG و آزمون هاست شخصی کاربر در این نوبت انجام نشده است. صوت، جایگزین غیرتصویری است؛ روش ورود بدون آزمون شناختی مانند passkey در این نسخه ادعا نمی‌شود.

این خروجی، PHP/MySQL مستقل است و با Worker نیمه‌مهاجرت‌شده متفاوت است. سورس PHP مرجع به پوشهٔ جدید منتقل و برای نصب مستقل، امنیت ورود، قراردادهای رابط و ذخیره‌سازی اصلاح شده است؛ فایل‌های مرجع منجمد تغییر نکرده‌اند.

## شواهد پایهٔ نسخهٔ php.1 برای بخش‌های بدون تغییر

- PHP واقعی `8.2.34` با `PDO_mysql`، `mbstring`، `OpenSSL`، cURL و zlib.
- MariaDB واقعی `10.11` در محیط ایزوله با داده‌های مصنوعی `TEST-TAMIRAN`؛ بدون تماس با هاست یا دیتابیس مشتری.
- نصب اولیه از HTTP روی loopback: ایجاد ۱۰۴ جدول، triggerها، حساب مدیر انتخاب‌شده و فایل تنظیمات خصوصی 600.
- آزمون نصب‌کننده: ۳۴ بررسی موفق؛ آزمون امنیت فرم نصب: ۱۴ بررسی موفق. شامل کلید خصوصی نصب، CSRF، قفل هم‌زمانی، جلوگیری از نصب دوباره و رد دیتابیس غیرخالی.
- ۲۰ آزمون موفق سرویس‌ها روی دیتابیس جداگانه: پشتیبان رمزگذاری‌شده، checksum، scope تعمیرگاه، فایل خصوصی، preview و بازیابی تراکنشی همراه بکاپ اضطراری، ابطال نشست، رد فایل مخدوش؛ OTP منقضی/مصرف‌شده/متعلق به تعمیرگاه دیگر و محدودیت تلاش حتی پس از rollback.
- ۱۹ بررسی readback واقعی دیتابیس برای رمزگذاری پیش‌نویس، یک‌بارگی سند/پرداخت، شناسهٔ دستگاه و prepareهای native.
- ۷۸ بررسی موفق HTTP/API: captcha واقعی، ورود مدیر و شش نقش، اجبار تغییر رمز و ادامهٔ نشست، ایجاد تعمیرگاه و retry، جداسازی tenant، تنظیمات/کاتالوگ/شرایط قبض، نسخه و مالکیت پیش‌نویس، مشتری و دستگاه قبلی، پذیرش و idempotency، انبار و ledger، گردش تعمیر، فاکتور و پرداخت نقدی و جلوگیری از پرداخت اضافه، CSRF/origin، چرخش نشست در ورود دوباره، ابطال نشست قبلی و خروج.
- ۲۳ بررسی رگرسیون موفق با ایجاد ۲۵۱ پذیرش واقعی از API: آمار کامل مستقل از صفحه، دو صفحهٔ بدون تکرار، رد offset نامعتبر، scope تکنسین، رد تخصیص V2 از PATCH عادی بدون تغییر رکورد، و تخصیص اتمیک هر دو مالک از API گردش‌کار. fixture صف دارای دو تکنسین است، چون طبق قاعدهٔ محصول، تنها تکنسین موجود خودکار تخصیص می‌گیرد.
- ساخت Vite و TypeScript سخت‌گیرانهٔ رابط مستقل موفق؛ هر بیست منوی رابط اصلی حفظ شده‌اند.
- مرورگر Chromium: ورود مدیر از فرم واقعی با captcha، نمایش پنل مرکزی، بازیابی نشست مدیر تعمیرگاه، نمایش داشبورد و پنج مسیر اصلی، عرض موبایل 390px بدون اسکرول افقی و بدون خطای JavaScript؛ ۹ بررسی موفق.
- ZIP نصب از پوشهٔ تازه استخراج و با کلید خصوصی روی دیتابیس خالی نصب شد؛ بسته شامل هیچ config تولیدشده یا دادهٔ آزمون نیست. صحت فایل‌ها با SHA-256 و صحت ZIP بررسی می‌شود.

## اصلاحات مهم نسبت به مرجع

- حذف ورود استیجینگ/انتخاب نقش آزمایشی و غیرفعال‌کردن endpoint بازنشانی راه‌اندازی قدیمی.
- HTTPS، cookie امن، انقضای idle/absolute، اعتبارسنجی عضویت سروری و ابطال credential؛ تغییر رمز اولیه نشست معتبر تازه ایجاد می‌کند.
- مجوز انتقال V2 پیش از replay، نگهداری prepareهای native با پشتیبانی placeholderهای نام‌دار تکراری و زمان‌های ذخیره‌شدهٔ UTC.
- version check و مالکیت پیش‌نویس، رمزگذاری محتوای پیش‌نویس، نسخهٔ دستگاه قبلی و پرونده، تطبیق محتوای شرایط نمایش‌داده‌شده هنگام پذیرش.
- هماهنگی صف autosave با ثبت، بازیابی دستگاه قبلی و حفظ اصلاحات مشتری در رابط.
- سرویس‌های خصوصی پیامک و پشتیبان‌گیری، حفاظت scope فایل‌ها و کلید نصب خارج از document root.
- شمارش کامل و دارای scope مستقل از سقف ۲۵۰ مورد، صفحه‌بندی صریح پرونده‌ها و تخصیص تکنسین V2 از مسیر گردش‌کار اتمیک.
- جلوگیری از نمایش فرم ورود روی HTTP عمومی، پیش از آنکه کاربر بتواند رمز را ارسال کند.

## محدودیت‌های آزمون

- نصب واقعی روی cPanel/DirectAdmin شخصی شما و قواعد Apache/LiteSpeed/Nginx همان هاست اجرا نشده است. آزمون HTTP محلی از router توسعه استفاده می‌کند؛ تنظیم document root و SSL در مقصد لازم است.
- مرورگر در نسخهٔ جاری شامل ۳۵ بررسی اصلاحات رابط و شواهد پایهٔ مسیرهای اصلی است؛ آزمون کامل تعاملی تمام بیست منو، چاپ A5، همهٔ نقش‌ها روی موبایل و همهٔ ترکیب‌های Solo/Pro/QC/انبار انجام نشده است.
- پرداخت آزمایش‌شده ثبت **نقدی مصنوعی** است؛ درگاه بانکی واقعی استفاده نشده است. پیامک واقعی و تحویل OTP از ارائه‌دهنده نیز آزمایش نشده و پیش‌فرض خاموش است.
- پشتیبان‌گیری این نسخه محلی و رمزگذاری‌شده است؛ ارسال به فضای خارج از هاست پشتیبانی نمی‌شود. بازیابی خودکار برای snapshot یک تعمیرگاه در همان نصب و همان ساختار SQL است؛ بکاپ کل برای نگهداری و بازیابی دستی است. اندازهٔ snapshot با تنظیمات و حافظهٔ PHP محدود می‌شود. زیرساخت زمان‌بندی هاست در این محیط فعال نشده است.
- ZIP نصب برای دیتابیس خالی است؛ ZIP به‌روزرسانی فقط فایل‌های نسخهٔ `php.1` را با حفظ SQL موجود ارتقا می‌دهد. انتقال یا مهاجرت خودکار از ساختار دیتابیس متفاوت وجود ندارد. MySQL 8 هدف سازگاری SQL است، اما اجرای این نوبت با MariaDB 10.11 انجام شده است.

گزارش‌های تفصیلی اجرای محلی در محیط کدکس زیر `/workspace/scratch/` نگهداری شده‌اند؛ ZIP نصب شامل دادهٔ آزمون، config تولیدشده، رمز دیتابیس آزمایش، log یا dependencyهای Node نیست.
