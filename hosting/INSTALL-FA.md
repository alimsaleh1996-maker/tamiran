# نصب تعمیران روی هاست PHP

این بسته برای نصب مستقل روی دامنه یا زیردامنهٔ شخصی ساخته شده است. روی هاست نیازی به Node.js، npm، Cloudflare یا ورود ChatGPT نیست. رابط HTML/CSS/JavaScript آماده و بک‌اند PHP و SQL در بسته موجودند.

## پیش‌نیازها

- PHP نسخهٔ 8.2 یا جدیدتر با `PDO_mysql`، `mbstring`، `OpenSSL`، `JSON`، `session` و `zlib`.
- MySQL 8 یا MariaDB 10.6 به بالا؛ آزمون نصب این نسخه با MariaDB 10.11 انجام شده است.
- دیتابیس **خالی و اختصاصی** و کاربر دارای مجوزهای SELECT، INSERT، UPDATE، DELETE، CREATE، ALTER، INDEX و TRIGGER روی همان دیتابیس. نصب‌کننده دیتابیس یا کاربر SQL نمی‌سازد.
- HTTPS فعال روی دامنه. PHP باید امکان نوشتن در پوشهٔ `private` خارج از ریشهٔ وب را داشته باشد.
- Apache/LiteSpeed برای استفاده از `.htaccess`. در Nginx باید document root و قواعد دسترسی معادل را خودتان تنظیم کنید.
- افزونهٔ cURL برای اتصال اختیاری به ارائه‌دهندهٔ پیامک. بدون تنظیم و فعال‌سازی صریح، پیامکی ارسال نمی‌شود.

کپچای صوتی فارسی از فایل‌های همراه بسته و PHP معمولی استفاده می‌کند؛ روی هاست به FFmpeg، موتور تبدیل متن به گفتار یا سرویس صوتی خارجی نیاز ندارد. پوشهٔ `private/captcha-audio` و فایل `private/captcha-audio.php` را همراه بقیه فایل‌های خصوصی منتقل کنید.

## ۱. بارگذاری در مسیر درست

در File Manager پنل هاست، به **پوشهٔ والدِ public_html همان دامنه** بروید و ZIP نصب را آنجا استخراج کنید. ساختار باید دقیقاً چنین باشد:

```text
domain-root/
├── public_html/
│   ├── index.php
│   ├── .htaccess
│   ├── assets/
│   ├── api/
│   └── install/
└── private/
    ├── install.php
    ├── install.key
    ├── config.example.php
    ├── database/schema.sql
    └── ...
```

در cPanel، اگر ریشهٔ سایت `/home/USER/public_html` است، `private` باید `/home/USER/private` باشد. در DirectAdmin معمولاً هر دو پوشه داخل `domains/DOMAIN/` قرار می‌گیرند. `private` را داخل `public_html` نگذارید. اگر زیر دامنه دارید، ابتدا document root آن را به `public_html` مربوط به همان بسته تنظیم کنید.

این نسخه باید در ریشهٔ دامنه نصب شود؛ نصب در نشانی‌هایی مثل `/tamiran/` پشتیبانی نشده است، چون API و assetها مسیر مطلق دارند. روی پوشهٔ سایت قبلی استخراج نکنید؛ ابتدا از آن نسخهٔ پشتیبان بگیرید و مقصد مجزا انتخاب کنید.

فایل‌های مخفی مانند `.htaccess` را نیز منتقل کنید. مالک فایل‌ها باید کاربر همان هاست باشد؛ `public_html` و زیرپوشه‌های عمومی معمولاً 755، فایل‌های عمومی 644، پوشهٔ `private` ترجیحاً 700 و فایل‌های خصوصی 600 باشند. از مجوز 777 استفاده نکنید.

## ۲. ساخت دیتابیس در پنل

در پنل هاست یک دیتابیس خالی و یک کاربر بسازید و کاربر را با مجوزهای بالا به آن متصل کنید. نام کامل دارای پیشوند پنل، رمز، host و port را نگه دارید. **قبل از اجرای نصب‌کننده SQL را در phpMyAdmin وارد نکنید**؛ نصب‌کننده جدول‌ها، triggerها و داده‌های پایه را خودش ایجاد می‌کند و روی دیتابیس غیرخالی متوقف می‌شود.

## ۳. اجرای نصب‌کننده

1. در File Manager فایل خصوصی `private/install.key` را باز کنید و کلید نصب را کپی کنید. کلید در صفحهٔ عمومی نمایش داده نمی‌شود؛ فقط مالک فایل‌های هاست باید آن را داشته باشد. ZIP نصب این فایل را دارد؛ اگر از سورس استفاده می‌کنید، یک‌بار صفحهٔ نصب را باز کنید تا فایل خصوصی ساخته شود.
2. `https://YOUR-DOMAIN/install/` را باز کنید.
3. کلید نصب، مشخصات دیتابیس، نام مدیر، موبایل مدیر و رمز مدیر را وارد کنید. رمز را خودتان انتخاب کنید؛ هیچ حساب یا رمز پیش‌فرضی وجود ندارد.
4. پس از نصب موفق، فایل `private/config.php` با دسترسی 600 ساخته و نصب دوباره قفل می‌شود.
5. به صفحهٔ اصلی بروید و با حساب مدیر وارد شوید. چالش امنیتی ورود را تکمیل کنید. از پنل مرکزی، تعمیرگاه، شعبه و کاربران موردنیاز را ایجاد کنید.
6. پس از ورود موفق، پوشهٔ عمومی `public_html/install` را از هاست حذف کنید. `private/install.php` و `private/database` را برای نسخه‌های بعدی یا عیب‌یابی مالک نگه دارید؛ این‌ها از وب قابل دسترسی نیستند.

اگر نصب SQL نیمه‌کاره ماند، نصب‌کننده جدول‌ها را خودکار حذف نمی‌کند. خطای مجوز/نسخهٔ SQL را برطرف کنید و برای تکرار یک دیتابیس خالی تازه بسازید. هرگز دیتابیس استفاده‌شده یا دارای دادهٔ مشتری را برای عبور از این خطا خالی نکنید.

## نگهداری کلیدها و داده‌ها

از **دیتابیس و کل پوشهٔ private با هم** پشتیبان بگیرید. کلید رمزگذاری در `config.php` و کلیدهای runtime برای خواندن پیش‌نویس‌ها و داده‌های رمزگذاری‌شده لازم‌اند؛ در به‌روزرسانی آن‌ها را جایگزین یا دوباره تولید نکنید. ZIP نصب تازه برای نصب تازه است و ارتقای خودکار دیتابیس موجود انجام نمی‌دهد.

پشتیبان داخلی این نسخه روی همان هاست به‌صورت رمزگذاری‌شده ذخیره می‌شود؛ یک نسخه از فایل‌های پشتیبان را خودتان به محل جداگانه منتقل کنید. ارسال خودکار به فضای خارج از هاست در این نسخه پشتیبانی نشده است. بازیابی خودکار فقط برای snapshot یک تعمیرگاه در همان نصب/ساختار SQL است؛ بازیابی کل سرور باید با نسخهٔ کامل دیتابیس و فایل‌های خصوصی و روش پنل هاست انجام شود.

زمان‌ها در دیتابیس UTC و نمایش تاریخ در رابط فارسی است. مبلغ‌های قرارداد برنامه به ریال و عدد صحیح ذخیره می‌شوند.

## HTTPS و پراکسی

در نصب معمولی SSL را مستقیماً در هاست فعال کنید. پشت reverse proxy فقط IPهای واقعی پراکسی را در `trusted_proxies` و گزینهٔ `trust_forwarded_proto` در فایل خصوصی تنظیم کنید؛ به هدرهای ارسالی هر کاربر اعتماد نکنید. نصب‌کننده نیز باید HTTPS واقعی دریافت کند. حالت HTTP در کد صرفاً برای تست محلی loopback است و برای دامنهٔ عمومی فعال نمی‌شود.

## پیامک و زمان‌بندی

ارسال پیامک در تنظیمات نصب خاموش است. برای استفاده، ابتدا تنظیمات ارائه‌دهندهٔ پشتیبانی‌شده را از پنل تکمیل و سپس `sms.enabled` را در فایل خصوصی فعال کنید. سرویس خارجی و ارسال واقعی در آزمون‌های این نسخه استفاده نشده‌اند؛ هزینه و تحویل پیامک باید با حساب خودتان آزمون شود.

در صورت نیاز، cron را **خودتان** در پنل تعریف کنید؛ نصب‌کننده هیچ cron فعال نمی‌کند. نمونهٔ دستورات با مسیر مطلق PHP و دامنهٔ خودتان:

```sh
/usr/local/bin/php /home/USER/domains/DOMAIN/public_html/api/sms-worker.php
/usr/local/bin/php /home/USER/domains/DOMAIN/public_html/api/backup-cron.php
/usr/local/bin/php /home/USER/domains/DOMAIN/public_html/api/retention-worker.php
```

پیش از فعال‌سازی retention، سیاست نگهداری را بررسی کنید؛ این job برای حذف داده‌های موقت است. زمان‌بندی‌ها را با نیاز و ظرفیت هاست تنظیم کنید. کلید cron را در URL عمومی یا query string قرار ندهید.

## عیب‌یابی

- خطای 500 در همان ابتدا: نسخهٔ PHP، افزونه‌ها، جای درست `private` و مالکیت/دسترسی فایل‌ها را بررسی کنید.
- خطای اتصال دیتابیس: نام کامل دارای پیشوند پنل، host، port و اتصال کاربر به دیتابیس را بررسی کنید.
- اگر ساخت جدول متوقف شد، مرحله، شمارهٔ دستور و کد SQLSTATE و کد عددی دیتابیس که نصب‌کننده نشان می‌دهد را برای پشتیبانی بفرستید؛ رمز، کلید نصب و اطلاعات اتصال را ارسال نکنید. چون دستورهای ساخت جدول در MySQL قابل rollback کامل نیستند، برای تلاش دوباره یک دیتابیس خالی تازه بسازید؛ هیچ دیتابیسی را بدون اطمینان از اختصاصی‌بودن و بررسی خودتان خالی نکنید.
- محدودیت فایل‌سیستم: نصب‌کننده پیش از ساخت جدول، نوشتن و جابه‌جایی فایل خصوصی را بررسی می‌کند و در صورت غیرفعال بودن `link` از روش جایگزین استفاده می‌کند. اگر بررسی نوشتن یا انتقال شکست خورد، مالکیت و مجوز پوشهٔ خصوصی را با پشتیبانی هاست بررسی کنید.
- خطای TRIGGER: از پشتیبانی هاست مجوز TRIGGER روی دیتابیس اختصاصی را بخواهید.
- خطای 426 یا ورود ناموفق با HTTP: SSL و نشانی `https://` را اصلاح کنید.
- خطای 404 روی `/software` یا `/tamiran`: انتقال فایل مخفی `.htaccess` و فعال‌بودن rewrite را بررسی کنید. در Nginx، fallback را فقط برای مسیرهای برنامه به `index.php` بدهید؛ فایل ناشناختهٔ API نباید به HTML تبدیل شود.
- `private/logs` شامل شناسهٔ پیگیری خطاهاست؛ آن را عمومی نکنید. اطلاعات اتصال را برای درخواست پشتیبانی در پیام یا اسکرین‌شات افشا نکنید.

## ثبت رویداد و عیب‌یابی

- پاسخ‌های API با شناسهٔ درخواست، نام endpoint، وضعیت HTTP و مدت تقریبی در فایل روزانهٔ `private/logs/tamiran-YYYY-MM-DD.log` ثبت می‌شوند؛ تاریخ و زمان فایل UTC است. رویدادهای مهم کسب‌وکار علاوه بر آن در جدول ممیزی مربوط نگهداری می‌شوند.
- خطاهای نصب نیز بدون نام کاربر، رمز و متن SQL در همین پوشه ثبت می‌شوند و شناسهٔ نصب روی فرم خطا نشان داده می‌شود. خطاهای مرورگر و قطع درخواست به‌صورت تلاش محدود برای ثبت نوع خطا و نام endpoint گزارش می‌شوند؛ متن خطا، stack و اطلاعات فرم ارسال نمی‌شوند. اگر مرورگر آفلاین باشد یا گزارش ارسال نشود، ممکن است رکوردی ثبت نشود.
- لاگ‌های جدید با مجوز خصوصی ساخته می‌شوند؛ مالکیت و غیرعمومی بودن کل پوشهٔ `private` را در هاست کنترل کنید. فایل‌های قدیمی ممکن است دادهٔ بیشتری داشته باشند. اگر ذخیرهٔ لاگ ناموفق شود، فقط یک هشدار کلی به PHP error log ارسال می‌شود و عملیات اصلی متوقف نمی‌شود.
- فایل‌ها روزانه ایجاد می‌شوند اما پاک‌سازی یا چرخش خودکار ندارند. مصرف فضای دیسک و سیاست نگهداری را در پنل هاست مدیریت کنید. به پشتیبانی فقط شناسهٔ درخواست، زمان و نام endpoint را بدهید؛ فایل کامل، رمز، کوکی، توکن یا دادهٔ مشتری را ارسال نکنید.
- خطاهای پیش از اجرای bootstrap، خطاهای وب‌سرور، قطع کامل شبکه و فایل‌های استاتیک ممکن است فقط در لاگ وب‌سرور یا مرورگر قابل بررسی باشند. نسخه Worker سامانه از این سازوکار PHP مستقل است.

## دامنهٔ آزمون این نسخه

جزئیات آزمون‌ها و محدودیت‌ها در `VERIFICATION-FA.md` همراه بسته ثبت شده است. موفقیت نصب به معنی آزمون همهٔ سناریوهای کسب‌وکار روی هاست شخصی شما نیست؛ پیش از استفاده از دادهٔ واقعی، پذیرش تا تحویل، نقش‌ها، چاپ و بازیابی را روی دادهٔ آزمایشی همان هاست بررسی کنید.
