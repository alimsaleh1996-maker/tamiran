# بررسی رابط تعمیران با UI UX Pro Max

وضعیت بعدی: اصلاحات این گزارش در [نسخهٔ 2.0.0-php.2](ui-ux-pro-max-fixes.md) انجام و با آزمون‌های جدید بررسی شدند. شواهد زیر، وضعیت نسخهٔ قبلی را حفظ می‌کنند.

نسخهٔ بررسی‌شده: **PHP hosting / 2.0.0-php.1**، فایل اجرایی مرورگر `index-Cqfh-3_Z.js`.

**نتیجه:** چیدمان فارسی، راست‌به‌چپ، هویت بصری و تفکیک سه‌مرحله‌ای پذیرش منسجم‌اند؛ بااین‌حال شش ایراد قابل بازآفرینی باقی است. اولویت اصلاح با نمایش داده هنگام خطا و مسیرهای کیبورد/دسترس‌پذیری است. این نوبت بررسی بود؛ کد محصول و ZIP منتشرشده تغییر نکردند.

## محدوده و روش

- استفاده از راهنمای `ui-ux-pro-max` در مسیر `~/.agents/skills/ui-ux-pro-max/SKILL.md`، با مسیر مخصوص **Review existing UI**؛ طراحی جدید یا تغییر خودکار theme انجام نشد.
- تشخیص stack از package.json: React 19، TypeScript، CSS آماده و APIهای PHP هم‌دامنه؛ پایگاه دادهٔ آزمایش MariaDB 10.11.
- بررسی واقعی در Chromium با PHP 8.2 روی loopback؛ یک تعمیرگاه، حساب‌ها و داده‌های واضحاً مصنوعی برای مشاهدهٔ رابط ساخته شدند. هیچ سایت، مشتری، پیامک یا پرداخت واقعی درگیر نشد.
- صفحهٔ ورود، داشبورد، پذیرش، انتخاب محصول، پنجرهٔ آدرس و منوی موبایل بررسی شدند؛ viewportها: `1440×1000`، `375×812`، `768×1024` و `812×375`.
- برای حالت خطا، فقط درخواست خواندن `operations.php` در مرورگر آزمایشی قطع شد؛ API و دیتابیس دست‌کاری نشدند.
- جست‌وجوهای محلی مهارت برای authentication، خطا و فوکوس فرم، contrast و برچسب‌های React اجرا شدند. نتیجهٔ dropdown پس از بازنویسی query به Keyboard Navigation رسید. برای focus trap، خروجی جست‌وجو عمومی بود؛ یافتهٔ مربوط به modal بر آزمون واقعی و الگوی عمومی WAI-ARIA متکی است، نه ادعای تطبیق کامل دادهٔ مهارت.

اولویت‌ها: **P1** یعنی مانع مسیر اصلی برای یک گروه از کاربران یا نمایش اطلاعات گمراه‌کننده؛ **P2** یعنی نقص مهم تعامل/خوانایی که باید در اصلاح بعدی رفع شود. این اولویت‌بندی، امتیاز یا گواهی انطباق کامل WCAG نیست.

## ۱. P1 — خطای بارگذاری به «صفر پرونده» تبدیل می‌شود

**شاهد کد:** [page.tsx:339](../frontend/src/app/tamiran/page.tsx#L339). شکست core تنها toast می‌سازد و بازمی‌گردد؛ `operations` مقدار اولیهٔ خالی را نگه می‌دارد و loading پایان می‌یابد.

**بازآفرینی:** یک پروندهٔ واقعی از API آزمایشی ساخته شد. داشبورد ابتدا «پرونده‌های فعال: ۱» و «منتظر تخصیص: ۱» نشان داد. پس از قطع درخواست خواندن عملیات و reload، هر دو به **۰** تبدیل شدند و پیام «هنوز اطلاعاتی ثبت نشده است» ظاهر شد؛ تنها هشدار، toast پایین صفحه بود. دکمهٔ «تلاش مجدد» وجود نداشت.

**اثر:** اپراتور می‌تواند نبود دادهٔ دریافتی را با نبود کار اشتباه بگیرد؛ نمای خالی با دادهٔ معتبر صفر یکسان دیده می‌شود.

**اصلاح پیشنهادی:** وضعیت‌های `loading / ready / error` را جدا کنید. در خطا، عدد نامعلوم یا آخرین دادهٔ موفق با برچسب قدیمی‌بودن نشان دهید؛ روی خود پنل، خطا و retry پایدار قرار دهید. صفر فقط پس از پاسخ موفق سرور نمایش داده شود.

**پذیرش اصلاح:** با یک پرونده و قطع API، عدد صفر و empty state موفق ظاهر نشود؛ retry بدون reload کامل داده را بازیابی کند.

شاهد تصویری: [داشبورد در خطای API](ui-ux-pro-max/dashboard-failed-api.png)؛ دادهٔ دقیق: [failure-evidence.json](ui-ux-pro-max/failure-evidence.json).

## ۲. P1 — انتخاب محصول با کیبورد کامل نمی‌شود

**شاهد کد:** [modules.tsx:2846](../frontend/src/app/tamiran/modules.tsx#L2846). combobox با blur پس از ۱۲۰ میلی‌ثانیه بسته می‌شود؛ handler کلیدهای جهت/Enter و `aria-activedescendant` ندارد. گزینه‌ها با کلیک انتخاب می‌شوند.

**بازآفرینی:** در مرحلهٔ دوم پذیرش، جست‌وجوی «مدل بررسی» نتیجهٔ محصول را نمایش داد. `ArrowDown` فوکوس را روی input نگه داشت و active descendant همچنان null بود. با `Tab`، فهرست بسته شد و فوکوس به `BODY` افتاد؛ انتخاب با کلیک همان محصول موفق شد.

**اثر:** کاربر متکی به کیبورد نمی‌تواند مسیر اصلی انتخاب محصول را به‌صورت عادی کامل کند. صرف داشتن `role="combobox"` رفتار کیبورد را ایجاد نمی‌کند.

**اصلاح پیشنهادی:** الگوی کامل combobox شامل ArrowUp/Down، Enter، Escape و گزینهٔ فعال را پیاده کنید؛ blur به گزینهٔ داخل popup نباید فهرست را زود ببندد. در صورت امکان از primitive دسترس‌پذیرِ موجود استفاده کنید.

**پذیرش اصلاح:** انتخاب یک محصول از ورود تا تأیید، فقط با کیبورد انجام شود؛ فوکوس گم نشود و گزینهٔ فعال به فناوری کمکی اعلام شود.

شاهد: [interaction-evidence.json](ui-ux-pro-max/interaction-evidence.json). شمارش خام `option` در این فایل، گزینه‌های select بومی رنگ را نیز شامل می‌شود؛ دلیل یافته، فوکوس/بسته‌شدن combobox و رفتار ArrowDown است، نه تعداد آن گزینه‌ها.

## ۳. P1 — ورود جایگزین غیرتصویری برای CAPTCHA ندارد

**شاهد کد:** [access.tsx:440](../frontend/src/app/tamiran/access.tsx#L440). تنها تصویر، refresh و ورودی پاسخ موجود است؛ مسیر صوتی یا جایگزین قابل استفاده برای کاربر نابینا در این فرم وجود ندارد. alt تصویر هدف را توضیح می‌دهد، ولی روش حل جایگزین فراهم نمی‌کند.

ورودی پاسخ نیز در DOM هیچ label وابسته یا `aria-label` ندارد. `<label>` بیرونی ابتدا به دکمهٔ refresh می‌رسد؛ متن قابل‌مشاهدهٔ «عبارت امنیتی» به input پاسخ متصل نیست.

**اثر:** ورود کارکنان به توانایی دیدن و خواندن تصویر وابسته است؛ یک گروه از کاربران از آغاز مسیر مسدود می‌شوند.

**اصلاح پیشنهادی:** روش احراز دسترس‌پذیر جایگزین یا چالش غیرتصویری با همان کنترل سوءاستفاده فراهم کنید؛ label صریح، id و توضیح مرتبط برای input قرار دهید. پاسخ CAPTCHA نباید در alt یا HTML افشا شود.

**پذیرش اصلاح:** یک کاربر بدون خواندن تصویر بتواند ورود امن را کامل کند؛ input پاسخ در درخت دسترس‌پذیری نام مشخص داشته باشد. آزمایش واقعی با صفحه‌خوان هنوز لازم است.

شاهد DOM: [initial-evidence.json](ui-ux-pro-max/initial-evidence.json).

## ۴. P2 — پنجره‌ها و کشوی موبایل فوکوس را مدیریت نمی‌کنند

**شاهد کد:** [Modal در modules.tsx:8634](../frontend/src/app/tamiran/modules.tsx#L8634) و [کشوی موبایل در page.tsx:1024](../frontend/src/app/tamiran/page.tsx#L1024).

**بازآفرینی پنجره:** با بازکردن «آدرس مشتری»، فوکوس روی دکمهٔ بیرون پنجره ماند. Tab بعدی به «ثبت مرحله و ادامه» در صفحهٔ پشت پنجره رفت. Escape پنجره را نبست، با اینکه `aria-modal="true"` اعلام شده است.

**بازآفرینی منوی موبایل:** فوکوس بعد از بازشدن روی دکمهٔ بازکننده باقی ماند؛ Tab به «پذیرش جدید» پشت backdrop رفت و Escape منو را نبست. دکمهٔ بازکننده `aria-expanded` نیز ندارد.

**اصلاح پیشنهادی:** فوکوس اولیه، محصورکردن فوکوس در نمای modal، Escape، بازگرداندن فوکوس به بازکننده و inertکردن پس‌زمینه را در primitive مشترک انجام دهید. برای دکمهٔ منو نیز رابطهٔ کنترل‌شده و حالت باز/بسته را اعلام کنید.

**پذیرش اصلاح:** تا وقتی پنجره/کشوی modal باز است، Tab به فرم پشت آن نرود؛ Escape ببندد و فوکوس به کنترل آغازگر بازگردد.

شواهد: [پنجرهٔ آدرس](ui-ux-pro-max/address-modal-keyboard.png)، [منوی موبایل پس از Escape](ui-ux-pro-max/drawer-mobile-after-escape.png) و دو JSON تعامل.

## ۵. P2 — کنتراست متن‌های راهنما و بعضی کنترل‌ها کافی نیست

**شاهد استایل:** [app-D2PBnnyi.css](../frontend/public/assets/app-D2PBnnyi.css)، قواعد `.stat-body small`، `.panel-heading p`، `.form-progress-item small` و `.field-helper`؛ اندازه‌های راهنما نیز در [beta7-ui.css](../frontend/public/assets/beta7-ui.css) بازتعریف می‌شوند.

اندازه‌گیری از رنگ محاسبه‌شدهٔ مرورگر و پس‌زمینهٔ مات همان عنصر انجام شد؛ متن روی gradient یا زنجیرهٔ نامطمئن و کنترل غیرفعال وارد این شمارش نشد.

| نمونه | اندازهٔ واقعی | رنگ متن / پس‌زمینه | نسبت | حد موردنیاز متن معمولی |
|---|---|---|---|---|
| «همه پرونده‌های باز» | 11.52px | `#8BA09F` / سفید | 2.75:1 | 4.5:1 |
| توضیح مرحلهٔ پذیرش | 11.52px | `#8EA19F` / سفید | 2.71:1 | 4.5:1 |
| راهنمای شمارهٔ موبایل | 10.5px | `#7F9592` / سفید | 3.17:1 | 4.5:1 |
| دکمهٔ «مشاهده پیگیری‌ها» | 13px، bold | `#1E8C86` / `#F8FCFB` | 3.94:1 | 4.5:1 |

در بخش قابل‌مشاهدهٔ دسکتاپ، ۹ نمونه در داشبورد و ۱۲ نمونه در مرحلهٔ اول پذیرش زیر حد بودند؛ این شمارش همهٔ صفحات پروژه نیست.

**اصلاح پیشنهادی:** نقش رنگ `muted-text` و رنگ متن دکمه‌های کم‌رنگ را در توکن‌های مشترک تیره‌تر کنید؛ اندازهٔ متن راهنما را نیز برای خوانایی عملی بازبینی کنید. کوچک‌بودن فونت به‌تنهایی معیار شکست WCAG نیست، ولی ترکیب آن با کنتراست پایین خواندن را دشوارتر می‌کند.

**پذیرش اصلاح:** همهٔ متن‌های معمولی فعال حداقل 4.5:1 داشته باشند؛ نسبت پس از ترکیب واقعی پس‌زمینه و alpha اندازه‌گیری شود.

شواهد: [داشبورد](ui-ux-pro-max/dashboard-desktop.png)، [پذیرش موبایل](ui-ux-pro-max/reception-mobile.png) و `contrastDashboard/contrastReception` در [JSON تعامل](ui-ux-pro-max/interaction-evidence.json).

## ۶. P2 — اولین Back مرورگر، صفحه را به خانه برنمی‌گرداند

**شاهد کد:** [page.tsx:392](../frontend/src/app/tamiran/page.tsx#L392). handler تاریخچه فقط وقتی `pageFromLocation()` مقدار معتبر داشته باشد صفحه را عوض می‌کند؛ بازگشت به URL اولیهٔ بدون `view` نادیده گرفته می‌شود.

**بازآفرینی:** ورود به `/` → انتخاب پذیرش → `/?view=reception` → Back. URL دوباره `/` شد ولی عنوان و محتوا همچنان «پذیرش تعمیرات» ماندند.

**اصلاح پیشنهادی:** برای URL بدون view نیز fallback مجاز نقش را اعمال کنید یا هنگام ورود، مسیر اولیه را با `replaceState` نرمال کنید. URL، عنوان و محتوا باید پس از Back/Forward هماهنگ بمانند.

**پذیرش اصلاح:** همین دنباله، داشبورد را برگرداند؛ Forward دوباره پذیرش را نشان دهد و مجوز نقش حفظ شود.

شاهد دقیق URL و عنوان: [interaction-evidence.json](ui-ux-pro-max/interaction-evidence.json).

## موارد مثبت مشاهده‌شده

- متن فارسی و راست‌به‌چپ در صفحه‌های بررسی‌شده درست نمایش داده شد؛ فونت و خانوادهٔ آیکن‌ها یکدست‌اند.
- صفحهٔ ورود و پذیرش در عرض‌های 375 و 768 و حالت افقی 812×375 اسکرول افقی نداشتند.
- labelهای ضمنی بیشتر inputهای عادی درست به کنترل مربوط بودند؛ نبود `htmlFor` به‌تنهایی به‌عنوان ایراد شمرده نشد.
- خطای پذیرش، summary قابل فوکوس دارد؛ کنترل IMEI ناقص نیز پیام مشخص نشان داد.
- هیچ خطای JavaScript صفحه در اجرای نمونه‌ها ثبت نشد. این نتیجه جایگزین بررسی همهٔ مسیرها نیست.

## ترتیب پیشنهادی اصلاح

1. جداکردن حالت خطا از دادهٔ صفر، retry پایدار و حفظ آخرین snapshot معتبر.
2. combobox قابل استفاده با کیبورد و primitive مشترک modal/drawer با فوکوس کامل.
3. ورود دسترس‌پذیر جایگزین CAPTCHA تصویری و اصلاح نام input پاسخ.
4. توکن‌های کنتراست، خوانایی متن راهنما و رفع fallback تاریخچه.
5. اجرای دوبارهٔ همین سناریوها و آزمون واقعی با NVDA/VoiceOver، سپس سایر منوها و چاپ.

## محدودیت‌ها و شواهد

بررسی روی نسخهٔ محلی PHP انجام شد؛ سایت ایستای آنلاین اولیه و Worker مهاجرتی موضوع این نوبت نبودند. آزمون کامل همهٔ بیست منو، همهٔ نقش‌ها، چاپ، dark mode، صفحه‌خوان واقعی و تنظیمات هاست مشتری انجام نشد. formal accessibility audit یا امتیاز Lighthouse ارائه نشده است.

شواهد ماشین‌خوان: [review-summary.json](ui-ux-pro-max/review-summary.json). فایل‌های بازآفرینی و خروجی جست‌وجوی مهارت در `/workspace/scratch/tamiran-ui-review/` نگهداری شدند. در اسکریپت دوم، حرکت به مرحلهٔ سوم به‌درستی به‌دلیل IMEI خالی رد شد؛ بنابراین تقویم مرحلهٔ سوم از این اجرا نتیجه‌گیری نشده است.

مرجع‌های عمومی الگو: [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)، [Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) و [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
