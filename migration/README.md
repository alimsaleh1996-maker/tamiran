# تعمیران — انتقال کنترل‌شده به Sites

راهنمای زیر سابقهٔ مهاجرت Worker را توضیح می‌دهد؛ نسخهٔ قابل نصب جاری در [hosting](../hosting/README.md) است. گزارش‌های گام‌ها در [docs/history/worker](../docs/history/worker/README.md) و بررسی‌های Worker در [docs/reports/worker](../docs/reports/worker/README.md) دسته‌بندی شده‌اند. مقصد توسعه و انتشار سورس طبق AGENTS.md، مخزن GitHub انتخاب‌شدهٔ مالک است.

شروع: ۲۴:۰۰ UTC در ۹ اکتبر / بامداد ۱۸ مهر ۱۴۰۵. هدف کاربر: جمعه ۲۴ مهر (۱۶ اکتبر).

## Scope Lock

- هیچ تماس، تست یا استقرار روی استیجینگ انجام نشود.
- تمام توسعه جدید در همین مخزن Sites با همان شناسه و دسترسی خصوصی انجام شود.
- منوها، قراردادهای API و قواعد کاری واقعی مبنا هستند، نه `dist/app.js` دموی قدیمی.
- انتقال بک‌اند PHP/MySQL به Workers/D1 با اثر آن بر خروجی مستقیم public_html توسط کاربر تأیید شده است.
- مجوز داده آزمایشی وجود دارد؛ رکوردها باید واضحاً آزمایشی، بدون مشتری/پیامک/پرداخت واقعی باشند. هیچ داده واقعی یا رمز سرور منتقل نشود.
- هیچ endpoint منتقل‌نشده پاسخ موفق ساختگی ندهد. هیچ role از URL، DOM یا انتخاب نقش مرورگر معتبر تلقی نشود.

## وضعیت واقعی گام اول

`worker/` پایه Vinext سازگار با Sites است؛ فعلاً جایگزین انتشار فعال نیست. رابط واقعی (۲۰ منو)، ۳۸ API PHP مرجع و موتور `v2-core.php` به‌صورت محلی و بدون اطلاعات runtime حفظ شده‌اند. PHP مرجع اجرا یا سرو نمی‌شود. CSS و فونت اصل حفظ شده‌اند؛ overlay تأییدنشده hybrid منتقل نشده است. تنها تفاوت قبلی پذیرفته‌شده در سورس رابط: انتخاب تکنسین از فهرست فیلترشده (اصلاح candidate قبلی).

`lib/workflow.ts` بخش برنامه‌ریزی انتقال را با ۸ ترکیب سیاست Solo/Pro، قطعات و QC از آرایه‌های PHP تطبیق می‌دهد. این برنامه‌ریز تراکنش دیتابیس نیست. خواندن facts از DB، optimistic update، رویداد، audit و مالی باید در یک عملیات اتمیک پیاده و آزمون شوند.

تقویت امنیت محدود: شناسه idempotency در نسخه PHP پیش از کنترل نقش بررسی می‌شد؛ در پایه جدید مجوز نقش و شعبه پیش از replay کنترل می‌شود. تست مستقل جلوگیری از replay غیرمجاز افزوده شده است. انتقال‌های خودکار داخلی، مجوز تجاری، انقضای ماژول‌ها و تولید facts از DB هنوز منتقل نشده‌اند.

تست واقعی: TypeScript پاس؛ build اولیه Worker پاس؛ ۵۵ تست واحد/تطبیق/دروازه امنیتی پاس. این نتایج به معنی E2E، ثبت پذیرش، صحت دیتابیس، رفتار چاپ یا آمادگی پایلوت نیستند. مرورگر QA در محیط فعلی طبق دستورالعمل Sites در دسترس نیست؛ هیچ مرورگر جایگزین یا preview بداهه راه‌اندازی نشده است.

## ترتیب ادامه و معیار خروج

1. D1 schema/migrations: حفظ روابط و محدودیت‌ها، شمارنده قبض بدون تداخل، عضویت و نقش سروری، دامنه شعبه/تعمیرگاه و idempotency. Migration فقط schema؛ seed آزمایشی جدا.
2. پذیرش: مشتری/دستگاه/اطلاعات ظاهری، حدود مجوز حذف اطلاعات، draft، ثبت اتمیک، شماره قبض و چاپ. آزمون دوبارکلیک، درخواست تکراری و rollback.
3. تکنسین: تخصیص، کارهای من، فیلتر/انتخاب، تشخیص و برآورد، تأیید مشتری و نقش همکار. ثبت سقف/مبلغ به‌صورت integer.
4. انبار/QC/مالی/تحویل: موانع هر مرحله، QC مشروط، تسویه و استثنای مدیر، OTP با محدودیت تلاش و بدون ارسال واقعی در داده تست.
5. مشتری: دسترسی محدود همان پرونده، تأیید/رد برآورد، OTP، نمایش تاریخ شمسی و عدم نشت پرونده دیگر.
6. کل منوها و تنظیمات: قابلیت/انقضا/نقش و چندشعبه؛ APIهای باقیمانده، پشتیبان/بازیابی و ثبت رویداد.
7. قبل از پایلوت: تست مرورگر دسکتاپ/موبایل، چاپ، بار/هم‌زمانی، بازیابی، E2E سه نقش و رگرسیون همه منوها. P0/P1 حل‌نشده = عدم اجازه شروع داده واقعی.

## اجرای تست‌های پایه

از `migration/worker`:

```sh
node --experimental-strip-types tests/workflow.test.mjs
node tests/source-preservation.test.mjs
node node_modules/typescript/bin/tsc --noEmit
```

Build فقط از helper رسمی Sites انجام شود. سورس مرجع frozen است؛ تغییر آگاهانه baseline مستلزم ثبت دلیل و تطبیق مجدد است. وضعیت فعال root هنوز static است؛ هنگام آماده‌شدن کامل، طبق دستورالعمل static-to-Worker همان project_id/audience حفظ و `static` حذف می‌شود. پایگاه داده یا دسترسی جدید بدون دلیل تغییر نکند.

یادآوری شخصی روزانه عصر تهران فعال است. ادامه توسعه خودکار جداگانه طبق `BACKGROUND-RUNBOOK.md`، `progress.json` و `QA-MATRIX.md` تنظیم می‌شود. ایجاد زمان‌بندی به معنی موفقیت اجرای آینده یا عبور خودکار از محدودیت مصرف نیست؛ هر اجرا باید checkpoint و evidence واقعی داشته باشد.
