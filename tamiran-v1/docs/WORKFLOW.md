# گردش مرحلهٔ اول

`assign` همان مسیر API سابق را دارد. قفل پرونده، ثبت مسئول، انتقال به `assigned` و رویداد جلوگیری از تکرار در یک تراکنش‌اند. تغییر مسئول موجود از مسیر ارجاع رسمی انجام می‌شود.

پذیرش و قطعی‌کردن ارجاع فقط با مسئول مبدأ معتبر و در مرحلهٔ قابل ویرایش فنی انجام می‌شوند. مدیر می‌تواند درخواست معلق را با علت لغو کند.
